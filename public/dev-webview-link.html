WebView 외부 링크 처리 가이드

앱이 없을 때 웹 URL로 보내는 fallback 경로 정리
핵심: 웹에서 앱 스킴(nmap://, kakaomap://)을 먼저 시도하고, 앱이 없으면 웹 URL로 보내는 로직이 이미 구현되어 있습니다. WebView에서 이 스킴들이 정상적으로 외부 앱 또는 외부 브라우저로 전달되도록 처리해주세요.
1. 네이버지도 길찾기
앱 스킴 (앱 설치 시) 앱 실행
nmap://route/car?dlat={위도}&dlng={경도}&dname={장소명}&appname=net.mypinpick
웹 fallback (앱 미설치 시) 브라우저 이동
https://map.naver.com/p/directions/-/{경도},{위도},{장소명},,PLACE_POI/-/car
1앱 스킴으로 1.2초간 앱 실행 시도
2앱이 안 열리면 위 웹 URL을 새 탭으로 오픈
2. 카카오맵 길찾기
앱 스킴 (앱 설치 시) 앱 실행
kakaomap://route?ep={위도},{경도}&by=CAR
웹 fallback (앱 미설치 시) 브라우저 이동
https://map.kakao.com/link/to/{장소명},{위도},{경도}
1앱 스킴으로 1.2초간 앱 실행 시도
2앱이 안 열리면 위 웹 URL을 새 탭으로 오픈
3. 네이버 예약
웹 URL (앱 스킴 없음) 브라우저 이동
https://m.place.naver.com/place/{naver_place_id}/booking?entry=plt
!앱 스킴 없이 처음부터 웹 URL로 이동합니다. target="_blank"로 외부 브라우저에서 열리도록 처리 필요.
요약
기능 앱 스킴 웹 fallback
네이버 길찾기 nmap:// map.naver.com
카카오 길찾기 kakaomap:// map.kakao.com
네이버 예약 없음 m.place.naver.com
WebView에서 처리해야 할 사항
iOS (WKWebView)
decidePolicyFor navigationAction에서 URL 스킴을 확인하고, nmap://, kakaomap:// 등 외부 앱 스킴은 UIApplication.shared.open(url)로 전달. canOpenURL이 false면 웹 fallback이 자동으로 동작합니다.
Android (WebView)
shouldOverrideUrlLoading에서 intent:// 및 커스텀 스킴을 Intent로 변환하여 startActivity. ActivityNotFoundException 시 S.browser_fallback_url로 이동.
공통: target="_blank" 처리
네이버 예약 등 <a target="_blank"> 링크는 WebView 내에서 무시될 수 있습니다. 외부 브라우저(Safari/Chrome)로 열리도록 처리해주세요.
